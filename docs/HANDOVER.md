## 0. Kurzfassung

- **Was:** Browser-Neuaufbau des Python/Ursina-Spiels „Might & Magic III“-Remake (`../old_code`) mit TypeScript 7, Babylon.js 9.31, Vite 8 und Vitest 5.
- **Zwei Spielweisen:**
  1. **Inselwelt** (`?seed=…&size=small|default|large|huge`): eine endliche, umlaufende Kugel aus Inseln mit sechs Klimata, Straßen, Flüssen und betretbaren Städten, Burgen, Dungeons, Höhlen, Pyramiden und einem Raumschiff. Alles folgt aus Seed und Größe; Innenräume und ihr Inhalt entstehen aus `(Weltseed, Ort)` und Regeln.
  2. **Kampagne** (`?campaign=1`): die 34 handgebauten Karten des Altspiels plus Testkarte mit Quests, Rätseln und Puzzles (50 Alt-Action-IDs). Im Hauptmenü ist „New Campaign“ ausgeblendet, der Code und gespeicherte Kampagnen laufen weiter.
- **Versionskontrolle:** Git (`origin` = GitHub `llange2/3D-RPG`, Hauptzweig `main`), ein Zweig je Auftrag; nach dem Merge wird der Worktree entfernt.
- **Der Altcode `../old_code` ist schreibgeschützt.** Er ist Quelle für Daten, Texturen, Modelle und Audio, nichts darin ändern.
- **Prüfung vor jedem Abschluss:** `npm run typecheck`, `npm test`; bei Generatoränderungen zusätzlich `GEN_VERSION`, `golden:update`, `check:chrome`; bei Renderingänderungen `check:render` und Browserprüfung (Abschnitt 13).

## 1. Hintergrund und Entscheidungen

Auftrag des Nutzers: auf Basis von `old_code` ein ähnliches, **seed-basiertes** Spiel bauen (alle Assets gehören dem Nutzer). Der „Never-ending Dungeon“ des Altspiels nutzte immer dieselben Texturen, kannte keine Außenlevel oder Burgen, und die Logik der „Actions“ musste von Hand gesetzt werden. Das Altspiel lief mit ca. 20 FPS draußen und 8 bis 15 FPS in Höhlen (pro Kachel 1 bis 3 Entities, 1,8 GB Assets, 10 bis 30k-Polygon-Modelle): Grund für den Neubau.

| Thema | Entscheidung |
|---|---|
| Plattform | Browser, TypeScript + Babylon.js (Vite, Vitest), Desktop-first, englische UI, kein Touch |
| Weltstruktur | Kugel aus Inseln (Abschnitt 6); Städte, Burgen, Dungeons, Höhlen, Pyramiden sind betretbare Orte, deren Innenleben aus `(Weltseed, Ort)` folgt |
| Altcontent | zuerst rein prozedural, die 34 Handkarten kamen danach als Kampagne |
| Actions | datengetriebene Regeln pro Ortsart, Koordinaten werden zur Generierungszeit über Anker aufgelöst; Story-Actions der Kampagne laufen in einer eigenen Engine |
| Kampf | **Gitterkampf, getaktet durch die Gruppe** (Monster handeln nach jedem Schritt und jeder Aktion der Gruppe), kein Echtzeit-Cooldown-Kampf |
| Isomorphie | Generator, Regeln und Simulation laufen ohne DOM und ohne Babylon (Node, Vitest, Web Worker) |

Nicht umgesetzt, obwohl im ursprünglichen Plan: WebGPU (`?gpu=`), `?pos=`/`?poi=`, Web-Worker-Meshing, ESLint-Boundaries (die Schichtung gilt per Konvention und Review), Lokalisierung, Touch und Gamepad.

## 2. Schnellstart

Voraussetzungen: Node v24, npm, Python 3.13 (nur für die Exportskripte), Google Chrome unter `C:\Program Files\Google\Chrome\Application\chrome.exe` (in `tools/dev/*` fest verdrahtet), Windows 11 mit Git Bash und PowerShell.

```
cd "C:\Sonstiges\3D RPG\game"
npm install          # nur bei neuem Checkout
npm run dev          # http://localhost:5173/
```

Der normale Dev-Server lädt die Seite bei jeder gespeicherten Datei neu und bricht laufende Browserskripte ab. Für Prüfungen neben anderen Jobs: eingefrorener Server auf **freiem** Port (`Get-NetTCPConnection -LocalPort` prüfen): `VITE_FROZEN=1 VITE_PORT=<Port> npx vite --port <Port> --strictPort`, dagegen `GAME_URL=http://localhost:<Port>/`; er übernimmt Änderungen erst nach einem Neustart.

| Parameter | Wirkung |
|---|---|

| `?dungeons=few\|default\|maximum` | Dichte der Höhlen und Dungeons (0,5 / 0,75 / 1); ohne Angabe **maximum** (alte Stände, Werkzeuge und Tests), das Hauptmenü nimmt `default` |
| `?autostart=1` | Titelbildschirm überspringen (Seed `test`) |
| `?outside=1` | neues Spiel auf der Überwelt statt vor dem Inn (für Werkzeuge, die die Überwelt messen) |
| `?campaign=1` / `?campaign=<slug>` | Kampagne, ggf. direkt auf einer Karte (Slugs: `public/assets/campaign/index.json`) |
| `?view=close\|medium\|far` | Sehdistanz (übersteuert das Menü) |
| `?debug=1` | FPS-, Draw-Call- und Dreieck-Overlay |
| `?bench=1&scenario=overworld\|interior\|campaign` | skriptierter Kamerapfad, Ergebnis in `window.__bench.result` |

### Steuerung

Alle Aktionen sind frei belegbar (Options > Controls, `game/keybindings.ts`, zwei Tasten je Aktion). Standard: W/S/A/D oder Pfeile (gehen), Q/E (90° drehen), Strg + Pfeil links/rechts (seitwärts), Leertaste oder Linksklick (Angriff), F (Zauber), I (Party Info/Inventar), 1 bis 4 (Held n), 5 (Maskottchen), T (Talente), R (rasten), M (Karte), J (Questbuch), Esc (Menü), F5/F9 (Quicksave/Quickload).

### Debug

- **Im Spiel:** Esc > Debug (Schalter `DEBUG_MENU` in `src/game/debug.ts`, nur im Dev-Server an, im Release aus): God mode, +10 Levels (mit Attributen und Resistenzen), +100k Gold, alle Zauber, alle Talente, Reveal map, Teleport to Level (**erster Eintrag: das Showcase**, danach alle Orte mit Quest und Layout), Identify (Theme, Klasse, Bewohner, Quest, Schlüsselrolle, Geheimnisse des Ortes), alle Schlüssel und Key Cards, Export/Import saves. Cheats lesen nur `applyHit` und `maintainGod`; neue Cheats gehören nach `debug.ts`.
- **Im Browser:** `window.__game` (`src/game/main.ts`): `game`, `state`, `world`, `camera`, `scene`, `teleport(x,y,facing)`, `enter(poiId)`, `goto(kind, service?)`, `gotoMonster()`, `firstPoi(kind)`, `leave()`, `campaign(slug,x?,y?,rot?)`, `campaignGoto(actionId, nth)`, `perf()`, `hashes(seed, chunks)`, `interiorHashes(seed, regions)`, `benchmark(scenario)`. Damit steuern `tools/dev/*` und die Tests den Browser.

## 4. Architektur

### Schichten und Isomorphie

```
core, data, world, interiors, actions, sim, campaign   → rein, deterministisch, KEIN DOM, KEIN Babylon  (laufen in Node/Vitest)
render, ui, audio, game                                 → Browser, Babylon, DOM
```

Die reinen Module importieren weder `document`/`window` noch `@babylonjs/*` (nur per Konvention und Review, kein ESLint). Einzige Ausnahme in `campaign`: `loader.ts` nutzt `fetch`, ist aber über `setCampaignFetcher` austauschbar. **Die Simulation entscheidet alles sofort**, die Darstellung läuft zeitversetzt: `Game.handleEvents` legt Flug, Log, Ton und Tod auf eine Zeitachse (`later`, `fxEpoch`); alles Verzögerte muss beim Szenenwechsel verfallen.

### Spielstand (`game/state.ts`, `game/saveCodec.ts`)

- Gespeichert werden **nur Seed und Deltas**, nie die Welt: `SaveFile { version, genVersion, savedAt, seed, state }` mit Party, Position, `opened` (Schlüssel der verbrauchten Aktionen und aller Merker, Reihenfolge zählt für die Gongs), `broken`, `killed`, `loot`, `explored` (Bitsets je Chunk bzw. Karte), `visited`, `steps`, `kills`, `size`, `dungeons`, `pirate`, `scale` (Belohnungsfaktoren der Welt), `hutSlots`, optional `campaign { progress, maps }`. Neue Felder sind optional, alte Stände laden mit Vorgabewerten.
- **Zwei Spielarten, zwei Speicherstände:** `GameKind` `world`/`campaign` (`kindOfState`, `readSave(kind, slot)`); neue Stellen, die laden oder neu starten, nehmen die Art des laufenden Spiels (`markResume(kind)`).
- **Plätze:** Quicksave (F5) und Autosave je ein Platz, dazu beliebig viele **benannte** Stände (`writeNamedSave`, `listNamedSaves`; Kampagnenstände erscheinen nicht in der Liste). Alles ist gepackt (`lz1:`): **jeder Lesezugriff auf den Rohstand geht durch `unpackSave`**, auch Werkzeuge. Stände ohne Indexeintrag kommen als „Recovered …“ zurück, Fehler beim Speichern zeigt ein Fenster. Debug > Export/Import saves überträgt alle Plätze als eine JSON-Datei.
- **Passwörter und Merker** der Quests, Fallen (`<uid>@fired`), Besuche (`<uid>@visited`), Hinweise (`clue:…`), Endräume (`<Karte>@end`) liegen als Strings in `opened`; nichts Eigenes im Format ergänzen, wenn ein Merker reicht.

## 5. Determinismus: die wichtigste Regel des Projekts

Alles Generierte ist eine **reine Funktion** von `(Weltseed, Ebene, Koordinaten)`. Nur so passen Chunk-Kanten, bleiben Spielstände gültig und stimmen Node und Chrome überein.

- **PRNG** (`src/core/rng.ts`): `sfc32`, Start über `cyrb128(seedString)`. Hilfen: `int(n)` (unverzerrt), `range(lo,hi)` (inklusiv), `chance(permille)`, `pick`, `weightedIndex`, `shuffle`, `float()` (nur fürs Rendering).
- **Ableitung:** `derive(parent, ...parts)` ist rein; `rngFor(seed, LAYER.x, ...coords)` ergibt unabhängige Ströme. Eigener Strom je Regel und Anker (`derive(mapSeed, ruleId, anchorIndex)`): eine neue Regel am Ende der Liste verändert frühere Ergebnisse nicht.
- **Kein Float in Entscheidungen**: Rauschen läuft in Q16.16-Festkomma (`noise.ts`). Verboten in `core`, `world`, `interiors`, `actions`, `sim`, `campaign`: `Math.random`, `Math.sin`, `Math.cos`, `Math.pow`, `Math.exp`, Lesen von Nachbar-Chunks.
- **`GEN_VERSION`** (`src/core/version.ts`, Verlauf im Kommentar der Datei): jede Änderung der Generator-Ausgabe erhöht sie. Einen Mehrversionen-Generator gibt es nicht; ein Spielstand einer älteren Version lädt in die neue Welt, `Game.migrateSave` bereinigt, was nicht mehr passt. Reine Darstellungsänderungen und Spielzeit-Formeln ändern sie nicht.
- **Golden-Hashes** (`tests/golden/world-hashes.json`, 100 Seeds, Größe je Seed): ein Unterschied ohne Update lässt `tests/unit/world.test.ts` fehlschlagen; `npm run check:chrome` prüft, dass Chrome dieselben Hashes rechnet.

**Ablauf bei Generatoränderungen:** ändern → `npm test` (Golden-Test schlägt fehl, erwartet) → prüfen, dass nur Gewolltes betroffen ist → `GEN_VERSION` erhöhen → `npm run golden:update` → `npm test` → `npm run check:chrome`. Zufall zur **Spielzeit** (Beute, Schlösser, Fallen) kommt aus eigenen Strömen je Aktion (`rngFor(root, LAYER.LOOT, uid, …)`, z. B. `<uid>@lock`, `<uid>@trap`): gleiche Truhe = gleiche Beute.

## 6. Weltgenerator (`src/world`)

Die Welt ist eine **endliche Kugel aus Inseln**. Die harten Regeln (Inselregeln des Nutzers, Lava, Hütten, Wildgruppen, Schutzzonen) stehen in `CLAUDE.md`; hier steht, wie die Teile zusammenhängen.

- **Größen** (`WORLD_SIZES` in `world/types.ts`): small 100 × 70, default 200 × 140, large 300 × 210, huge 400 × 280 Kacheln (immer breiter als hoch), 1 / 2 / 3 / 4 Städte je Stufe. Kachel 3 Welteinheiten (`TILE_SIZE`), **Chunk 10 × 10** (alle Größen sind Vielfache von zehn). Eine Kachel hinter der Kante ist die gegenüberliegende (`wrap`, `wrapDelta`, `World.wrapX/Y`): Spielerkoordinaten laufen ohne Sprung weiter, alles mit Identität (Orte, Wildgruppen, Beute, Erkundung, Maskottchen, Wagen) kennt nur die Weltposition und wird als Kopie neben der Gruppe gezeichnet.
- **Inseln** (`islands.ts`, `buildLayout`): Level 1 und 2 teilen die große Startinsel (Starthaven am äußersten Ende der Level-1-Hälfte, die Stadt der Stufe 2 am anderen), eine Brücke verbindet sie mit der Level-3-Insel, Level 4 und 5 haben eigene Inseln (die entferntere Hauptinsel ist Stufe 5), dazu weitere große und kleine Inseln der Stufen 4 und 5 (nie mehr kleine als große; die Grenze zwischen 4 und 5 liegt dort, wo beide **etwa gleich viel Land** haben). Landanteil 50 / 46 / 43 / 40 %. Jede Insel hat **ein** Klima und ist ein Raster für sich (`Island.field`) mit eigener Form (Kontinent, Oval, Dreieck, Streifen, Bucht mit Inselchen), nie ein Kreis. **Lavainseln** (Stufe 5 immer, bei large und huge eine zweite) bestehen nur aus Bergen und Lava; Wege sind Lavaströme, jeder Schritt auf Lava kostet 25 Feuerschaden (`sim/lava.ts`). Inselregeln nie in `World` zurechtbiegen, sondern in `makeSpec`/`buildLayout`; messen mit `tools/dev/island-stats.ts`, `corner-stats.ts` (muss 0 melden).
- **Gelände:** Land ist, wo die Randfunktion einer Insel positiv ist; Berge aus eigenem Rauschen, Wälder (`WOOD_*`), Flüsse je Klima (`RIVERS`), Vegetation auf einem Gitter mit mindestens zwei freien Kacheln nahe Wegen. **Ufer ist flach** (`World.settle`), ein Ort ist von zwei Kacheln Land umgeben, Wasser neben Straße oder Lava ist Land, wo es keine Mischkachel gäbe (`World.rawTile`). **Pässe durch Berge sind höchstens fünf Felder lang** (`World.lump`, `insideMass`, `opensUp`, `tests/unit/mountainPasses.test.ts`). Wer Gelände ändert, misst die Begehbarkeit über mehrere Seeds.
- **Orte** (`World.plan()` plant alle Inseln beim ersten Zugriff): eine Stadt/Burg/Höhle/Dungeon je 60 Landkacheln einer Insel (`LAND_PER_PLACE`), Mindestabstand 6; ID `p:<Insel>:0:<Index>`, Starthaven ist `p:0:0:0`. **Jeder Ort hat eine feste Eingangsseite, jeder Weg endet dort** (`Poi.side`, `poiEntrances`): Stadt und Burg 2 × 2 Kacheln (zwei Eingangskacheln, der Weg einer Stadt endet an der rechten), Pyramide 3, Turm 2, Dungeon und Höhle 1. Straßen sind gerade Stücke mit rechten Winkeln (`RoadSeg`), Brücken über Wasser. Bei Ankunft auf der Eingangskachel fragt das Spiel einmal, ob man eintritt (`Game.onArrived`, `askedPoi`); wer gegen den Ort läuft, wird weiter gefragt (`onBlocked`).
- **Plan der ganzen Welt** (`planPlaces` in `interiors/dungeonPlan.ts`, aufgerufen in `World.plan`): gibt jedem Höhlen- und Dungeonort Quest, Layout, Aussehen und seine Rolle in der Kette (Abschnitt 7); `World.planCastles` wählt die drei Burgen (gut, neutral, böse, auf Orten der Stufen 2, 3 und 4); `thinOutPlaces` streicht je nach `DungeonDensity` gewöhnliche Höhlen und Dungeons (Städte, Burgen und Pyramiden nie); `planSpellLoot` verteilt die Zauberrollen.
- **Stufe und Monster** (`difficulty.ts`): `World.tierAt(x, y)` (Insel der Kachel), `levelAt` (Stufe der Insel plus Weg zur nächsten Stadt), `wayAt` (0 bis 1000 nach Entfernung zu Starthaven, über alle Inseln der Stufe). **Wilde Gruppen sind für die ganze Welt geplant** (`planOf` in `spawns.ts`: je Insel `max(1, round(Fläche / 90))` Gruppen, gleichmäßig verteilt, mindestens eine je Insel; die Gruppen jeder Stufe teilen sich die Monster gleichmäßig: `planOf` setzt erst alle Gruppen der Welt, `spotShares` in `difficulty.ts` gibt jeder den Rang unter den Gruppen ihrer Stufe, seit `GEN_VERSION` 71; Messung `tools/dev/wild-stats.ts`, Test `tests/unit/wildEvenL5.test.ts`, Zahlen `docs/WELT_BELOHNUNGEN.md` Abschnitt 3); das offene Meer hat eigene Gruppen (Piranha, Octobeast). Schutzzonen: `SAFE_RADIUS` 3 um Starthaven und den Startpunkt, starke Gruppen halten 12 Kacheln Abstand (`safezone.ts`). Landmonster betreten nie Flachwasser. Wilde Monster und Maskottchen stehen nur auf Boden, der der Gruppe offen ist (`World.isOpenGround`).
- **Hütten** (`huts.ts`): eine Zahl in Entity 9 der Monstertabelle = eine Hütte je Monster mit 4 / 6 / 8 / 10 einzelnen Monstern (small … huge) im Umkreis von 5 Kacheln; die Hütten einer Stufe stehen nach Monster-XP von nah nach fern zu Starthaven und weit auseinander. Die Monster stehen nicht in `chunkSpawns`, sondern in `Game.placeHutMonsters`; Auffüllen je Woche über `GameState.hutSlots`, niedergebrannt = `hut:<id>@burnt`. Texte `data/hut-texts.ts`.
- **Karawanen und Landmarken** (`caravans.ts`): je Talent eine Karawane (Händler), jede dritte als Cottage; verschlossene Dungeons und Pyramiden haben eine Hinweis-Karawane im Umkreis von drei Feldern (`hintWagonOf`, Worte `data/caravan-hints.ts`); Brunnen, Fountains und Steinköpfe sind Landmarken, jeder dritte gibt einen zwölfstündigen Bonus (`game/landmarkBoons.ts`, `sim/boons.ts`). Was blockiert (Maskottchen, Wagen), fragt `World.leavesPassage`/`keepsRingOpen`.
- **Maskottchen** (`mascots.ts`): vier wilde nahe dem Start, die Krähe auf dem Platz der Startstadt; Regeln der Altaktion 13 (`data/mascots.ts`). **Piratenschiff** (`pirate.ts`, `Game.pirateTurn/pirateMeeting/syncPirate`): in der Mitte des größten Ozeans, fährt nur in Sichtweite, Begegnung nur auf dem Floß; Zahlen und Regeln in Abschnitt 7 (ue_quest_4).
- **Schwimmen und Segeln:** Flachwasser betritt nur, wer schwimmen kann (Swimmer, Seafarer, Zauber), tiefes nur, wer segeln kann (Seafarer, Walk on Water; das Floß liegt dann unter der Gruppe, `Game.syncRaft`). Rasten geht nie auf Wasser.
- **Start eines neuen Spiels:** Starthaven vor dem Inn (`innStart`, `Game.newGame`); der Start steht nie vor einer Wand (`actions/startSpot.ts`).
- **API:** `new World(seedText, size, density)`, `tile(tx,ty)`, `chunk(cx,cy)` (`ChunkData` mit Typed Arrays; `chunk()` und `tile()` müssen übereinstimmen), `poiById`, `poisInRect`, `startPosition()`, `chunkHash(chunk)`.

## 7. Innenräume, Actions und Quests

### Generatoren (`src/interiors`)

`generateInterior(world, poi, floor)` wählt nach Art und Layout; RNG `rngFor(root, LAYER.INTERIOR, poi.x, poi.y, floor)`, Schlüssel der Karte `<poiId>:<floor>`.

| Dungeon (`dungeon_1` Tube, `dungeon_2` Hub, `dungeon_3` Labyrinth, `dungeon_4` klassisch) | `dungeon_1/2` kompakt: 8 bis 15 Räume auf 72 × 72, Mauerabstand etwa 3 (`joinRooms`); Labyrinth 25 / 33 / 39 / 47 / 55 Zellen für Stufe 1 bis 5; **kein gerader Gang über 8 Zellen** (`MAX_STRAIGHT`, `bendLongCorridors`). Messen mit `tools/dev/layout-stats.ts` |
| Höhle (`cave_1` bis `3`) | Zellulärautomat, 40 × 40, Kammern, Mauerinseln (`addIslands`: nur wo drei Zellen ringsum offen sind, immer zwei Zellen Weg) |

| Burg | nur Bergfried (17 bis 21 Zellen je Seite) nach einem der zwei Pläne des Dokuments (`data/castle-plans.ts`, gedreht und gespiegelt), unter freiem Himmel; Inhalt aus `actions/castle.ts`, nicht aus Regeln |
| Stadt | Grundrisse der fünf Altstädte (`data/town-blueprints.ts`, 8 Lagen), Läden als Straßenzellen mit Tür in der Rückwand, Verkäufer und Deko als `InteriorMap.sites` |

| Showcase | dunkler Saal mit jedem Monster, jeder Persona und jedem Objekt auf eigener Zelle, ohne Funktion (Debug > Teleport, erster Eintrag); **wer ein Monster, Objekt oder Licht ergänzt, sorgt dafür, dass es dort zu sehen ist** (`tests/unit/showcase.test.ts`) |

`CELL`: `SOLID, FLOOR, PILLAR, BUILDING, LOW` (`LOW` nur Kampagne). `InteriorMap` trägt `cells`, `rooms`, `exit`, `spawn`, `theme`, `tier`, `sites`, `dungeon` (`DungeonRef`: Quest, Layout, Aussehen, Schlüsselrolle, Endraum, Schatzkammern), optional `styles` (Kampagne). **Themes** (`data/interior-themes.ts`): fünf Texturfamilien (dungeon, cave, fortress, cyber, town) in Varianten (lava, ice, swamp, desert, snow); Cyber gehört allein dem Raumschiff. **Wandhöhe je Art wie im Altspiel** (`wallHeightOf`: Dungeon und Cyber 4,5, Festung 4,2, Stadt und Höhle 3): nie alle Arten auf `CELL_SIZE` zwingen (`tests/unit/interiorMesher.test.ts`). **Topologie** (`topology.ts`): Räume, Mündungen, Tiefe, Sackgassen; daraus die Anker `exit, mouth, deadEnd, roomCenter, roomEdge, corridor, bossRoom, lot, wallBetween, street, beforeTreasure`. **Jede Suche über eine Karte folgt den Sprüngen der Treppen** (`interiors/stairs.ts` `stairLinks`).

### Quests der Welt

Quelle ist `docs/quests_1.10.md`; der Plan der **ganzen Welt** entsteht in `planPlaces` (`interiors/dungeonPlan.ts`, Tabelle `data/quest-table.ts`): jeder Ort bekommt Quest (`quest_1` bis `quest_8`), Layout und Aussehen (`buildLook`: Monster nach Typ und Stufe, Falle, Deko, Truhe, Schrein) und seine Rolle in der Kette: bis zu neun Schlüssel in Endräumen von Stufe 1 und 2 (verschlossen sind Dungeons der Stufen 3 bis 5, soweit die Schlüssel reichen, Höhlen nie), fünf Pyramiden (eine je Sektion, gleichmäßig über die Inseln) mit je einer Key Card in einem verschlossenen Dungeon der Stufe 4 oder 5, 23 Orbs auf Dungeons der Stufe 5 (dazu 2 je Sektion außer der Brücke im Schiff, also 8), Quatloo-Münzen, Silberschädel, Perlen, Artefakte. `checkKeyChain` prüft die Kette; **neue Orte, die an die Kette hängen, müssen mit gestrichenen Orten funktionieren** (`tests/unit/sfxMenuRobots.test.ts`).

- **Endraum** (`interiors/endRoom.ts`, Inhalt `actions/endRoom.ts`, `Game.openEndRoom`): jeder Ort hat einen, versiegelt (Wandzelle `seal`, die die Quest öffnet) oder als Tasche im Fels (`isolated`, Teleport durch die Quest). Inhalt nach `END_LOOT` (Pakete von Attributen oder Resistenzen, XP, Levelaufstieg, Resistenzkristall, Treasure eine Stufe über dem Ort). Kein Zauber trägt die Gruppe in einen verschlossenen Endraum (`Game.inClosedEndRoom`).
- **Rätsel** baut `actions/questGen.ts`, `questChecks.ts` prüft sie auf Lösbarkeit: Statuen, Gongs mit Runen (Quest 3: sichtbar sind nur die Runen des zuletzt geschlagenen Gongs), Kopf-Ring (Quest 2: Endraum an der Hallenwand oder Tasche, zu der Runen der Halle teleportieren), Kartenbild, Sprungfeld, Koordinaten, Boss (Quest 5, die zehn Paare `BOSS_PAIRS`). **Quest 8 (Crystal paths)**: reine Logik in `actions/crystals.ts` (`simulateCrystals`), der Generator `crystalGen.ts` beweist jedes Rätsel in vier Aufstellreihenfolgen; aufgestellte Kristalle als `crystal:<Karte>@x,y#seq` in `opened`, `Game.syncCrystals`. Quest-Objekte stehen nie in einem Durchgang und nie hinter einer versteckten Wand. Rätsel der Welt: `data/riddles-world.json` (bereinigt: ein Wort von 3 bis 8 Buchstaben, höchstens vier Rätsel je Antwort, keine Anachronismen; Ausnahmen im Exporter `DROP`/`ADD`), die Kampagne behält `RIDDLES_MASTER`.
- **Schatzkammern** (`actions/vaults.ts`, `carveVaults`): jede Höhle und jeder Dungeon hat 0 bis 3 Taschen im Fels hinter einer brüchigen Wand (`<Karte>#brittle:<n>`) mit einer Truhe doppelter Beute, mit 10 % Attribut- oder Resistenzpunkten der Stufe darunter (`VAULT_BONUS_CHANCE`). Münzen, Schädel und Rollen liegen nie darin; neue Regeln, die Zellen vergeben, achten auf `protectedCells`.
- **Mini-Quests** (Extra Loot): Quest-Truhen mit mehr Beute nach einer Formel aus Truhe und Schwierigkeit (höchstens das Zwölffache); Gerüchte der Taverne sind je zur Hälfte ein Passwort aus den Rätseln oder ein Spruch (`tavernRumour`).
- **Zauberrollen** (`interiors/spellPlan.ts`, `actions/spellScrolls.ts`, `data/spell-loot.ts`): jeder Zauber (außer Startzaubern) liegt **genau zweimal** in der Welt, je Kopie in einem anderen Ort der Stufe des Zaubers, in Truhe, Fass, Schatzhaufen oder Bücherregal. Nichts anderes erzeugt Rollen (`tests/unit/playtest34.test.ts` zählt nach).
- **Burg** (`actions/castle.ts`): König (nimmt die Orbs, `Game.meetKing`), Thron, vier Statuen mit Vier-Buchstaben-Wort, zwei Königstruhen (5 Mio Gold, Siegel, Alarm), Nischentruhen, Banner; Monster nur als Wachen, die der Alarm ruft (`guardsOf`, `Game.spawnGuards`); Nebenräume nie leer (`emptyRooms`); der Handlanger (`CastleLayout.keeper`) nimmt Artefakte zurück (`data/keepers.ts`). Der erste König mit elf Orbs gewinnt (`king:winner=<Art>`), die anderen Burgen sind Trümmer.
- **Raumschiff** (`actions/spaceship.ts`, `interiors/spaceship.ts`): Roboter, Kristalle, Computer (Item 68, Text auf dem ComputerScreen), Kisten (`CRATE_ITEM` 301), Schiebetüren und Schleusen; Licht des Schiffs `Game.syncShip`, Triebwerksbrummen über `ENGINES_FLAG`; die Konsole der Bridge braucht laufende Engines, Life Support und die schwarze Key Card (`Game.playEnding`, Outro `public/assets/ui/outro.mp4`, eingecheckt). Die Brücke: sieben Terminatoren, zwei Titanic Automatos, Konsole mit vier Wachen, verschlossene Tür zum Generatorraum mit dem Temporal Field Generator.
- **ue_quest_4, Piratenkönigin:** 20 Perlen (`PEARL`) in Truhen der Orte der Stufen 3 und 4 (`DungeonRef.pearls`) und in Alarmtruhen der Burgen; das Schiff (`world/pirate.ts`, Modell `obj_pirate_ship`) fährt nur in Sichtweite, 3 Felder je Schritt, die Begegnung gibt es nur auf dem Floß, danach ist es eine Woche weg (`GameState.pirate`); Dialog mit Sprecherbild `UI.scene`. Wer neue Wegsuchen im Wasser baut, fragt `pirateAt`.
- **Quatloo-Münzen und Silberschädel** (`actions/machines.ts`): in gewöhnlichen Truhen, Seth Squirm und die Maschinen in einem Dungeon der Stufe 2; der Schädel-Geizhals (`skullmiser`) in einer Sackgasse von Starthaven.
- **Questbuch** (`game/questLog.ts`, Taste J): alles wird aus dem Weltplan und Merkern in `opened` gelesen (`lock:<Ort>`, `reached:<Ort>`, `skullmiser:met`, `king:…`, `clue:…`); ein neues Quest-Ereignis bekommt dort eine Zeile (offen und erledigt) und einen Merker. Die Karte hängt bei erreichtem Endraum einen grünen Haken an den Ort.
- **Belohnungen sind pro Welt skaliert** (`actions/rewardScale.ts`, `rewardMeasure.ts`, `GameState.scale`, Formeln `FORMULAS_1.3.md` 7.6, Zahlen `docs/WELT_BELOHNUNGEN.md`): Belohnungen laufen durch `scaleAction` (Eingang von `resolveAction`), `scaledGold`/`scaledXp` und `Encounter.xpScale`, nie einzeln skalieren; die Zahlungen der Quest-Geber nie. Ein neuer Behälter mit Gold oder Punkten nimmt den Parameter `gold`/`amount` mit `bonus` bzw. `effect`; ein neues Belohnungsziel gehört in `REWARD_TARGETS`.

### Quests im Detail (Umsetzungsentscheidungen)

Die Quests selbst beschreibt `docs/quests_1.10.md`; hier steht, wie sie umgesetzt sind und wo das Dokument etwas offen ließ.

- **Layouts Dungeon** (`interiors/dungeon.ts`): `dungeon_1` Schlauch aus Räumen auf einer Schlange oder Spirale; `dungeon_2` Halle mit Ringen aus Räumen, **jede** Wegmündung bekommt Tür oder Gitter; `dungeon_3` Labyrinth (Gänge und Wände je ein Feld, kleine Räume, keine Türen, Teleportfelder auf aufgebrochenen Schleifen, ohne sie ganz begehbar); `dungeon_4` klassisch mit kleinen Kammern mit großem Schatz; `dungeon_5` Turm. Laternen (Item 76) stehen in allen Dungeons. **Layouts Höhle** (`interiors/cave.ts`): `cave_1` Ring 2 bis 3 breit mit Auswölbungen und inneren Kammern; `cave_2` Zellulärautomat; `cave_3` Baum aus Kammern, jede nur über einen Weg. Die Layouts sind Stilvorlagen, keine Kopien der Beispielkarten.
- **Quest 1 (stöhnende Statuen):** Eingangsraum 9 × 9 mit einem 3 × 3-Feld; acht Statuen (`head`, `mode: "moan"`), je ein Hebel und vier Dummy-Hebel; Lösung die vier Ecken oder (30 %) eine Seite, der Start ist nie die Lösung; die leere Mitte (`rune`, `need: "moan"`) teleportiert in den Endraum. Nie im Labyrinth. Jeder Hebel in einem Ort mit Köpfen spielt `stone_move`.
- **Quest 2 (Gesichter):** fünf Kelche (`chalice`, Zahl 1 bis 5 und Richtung) mit Zuständen (Stufe 1/2: Poisoned, Diseased, Crazy, Cursed; ab 3: Petrified, Dead, Paralyzed, Rotten, mit allen Fristen), fünf Köpfe (`head`, `mode: "rotate"`) in einer Reihe an einer Wand der 11 × 7-Halle, Kopf 1 links vom Blickenden; ein Kopf dreht sich animiert um eine Vierteldrehung (Dauer = Ton 9050); der letzte richtige öffnet den Endraum.
- **Quest 3 (Gongs):** vier (oder fünf) Gongs in den Räumen nahe den Ecken, je 5 bis 7 Monster aus dem Pool des Ortes (Typ `beast` oder `plant`); nach dem letzten Gong erscheinen Runen (`rune`, `need: "gongs"`) und teleportieren in den Endraum. Ein Gong ruft die Monster nur beim ersten Schlag.
- **Quest 4 (Rechnen):** fünf bis acht Statuen mit Tafeln, Endstatue nahe dem Endraum (`riddle`, Antwort = Summe, höchstens dreistellig); `questChecks` rechnet nach. **Quest 5 (Endgegner):** Bevölkerung = Stufe des Ortes, Boss das Paar aus der Tabelle (`BOSS_PAIRS`), er steht vor der Siegelwand, sein Tod öffnet den Endraum (`isEndBoss`); nur hier gibt es einen echten Boss (sonst ist `theme.boss` das stärkste gewöhnliche Monster, es bewacht den tiefsten Raum). **Quest 6 (Rätselwort):** ein Wort aus der Liste, eine Statue je Buchstabe mit Geschichte (`data/letter-hints.ts`), die Antwortstatue nahe dem Endraum; die Taverne kann das Wort verraten. **Quest 7:** das Raumschiff. **Quest 8:** Crystal paths (oben).
- **Mini-Quests:** jeder Ort trägt 0 bis `MAX_MINIS` (2/3/4/4 nach Weltgröße); die Gesamtzahl ist so begrenzt, dass jedes Rätsel höchstens einmal in der Welt vorkommt. Statue oder Kristall mit einem Rätsel; Antworten leicht (beliebig viele) oder schwer (drei, danach schweigt sie); bei falscher Antwort nichts, Wegteleport (×2) oder Fallenfeld (×3, eine einzelne Falle des Ortes); Belohnung = 2 × normale Truhe × Schwierigkeit. **Gerüchte:** ein Drittel der Taverne-Runden verrät ein Wort (`wordRumour`): zu 70 % die Antwort eines Rätsels aus einem Ort bis eine Stufe über der Taverne, sonst die eines unbenutzten.
- **Kelche und Punktepakete:** Levelaufstieg, Attributspunkte und XP der Endräume liegen in Behältern (Aktion `chalice` mit `bonus`, Fass, Brunnen, Kristalle auf Stufe 1 bis 3, Kelch ab Stufe 4, `ATTRIBUTE_VESSELS`); der Spieler wählt, wer trinkt, **nur dieser Held** bekommt den Bonus. Der Hinweis im Auswahlfenster nennt nie das Attribut, nur Farbe und Zeichen (`ATTRIBUTE_LOOKS`). Dasselbe gilt für die Kelche der Brücke des Raumschiffs.
- **Orbs und Könige:** 31 Orbs in der Welt (23 auf Dungeons der Stufe 5, 8 im Schiff), je Orb 1 Mio Gold (Gruppe) und 1 Mio XP je Held; **alle** Orbs im Rucksack werden mit Bestätigung abgegeben, der erste König mit 11 Orbs gewinnt (schwarze Key Card), die anderen Burgen sind Trümmer; drei Könige brauchen 33, es gibt 31: der Sieger zerstört die anderen. Gesinnung gut/neutral/böse verteilt sich zufällig auf die Burgen der Stufen 2, 3 und 4; Wachen: Gruppe nach Gesinnung (gut `humanoid`, neutral `magical_construct`, böse `undead`), leichte = Stufe der Burg, schwere = +1, genau zwei verschiedene Monster je Burg; sie werden beim Alarm gesetzt und nicht gespeichert (das Flag des Alarms bleibt).
- **Quatloo-Münzen:** 25, in gewöhnlichen Truhen der Orte der Stufen 1 bis 3 (höchstens 4 je Ort) und je 2 in der Burg der Stufen 2 und 3; in einem Dungeon der Stufe 2 steht hinter einer Tür ein Raum mit Seth Squirm (Persona 90) und sieben Statuen (eine Sorte je Weltseed), je Attribut eine: Münze und Heldenwahl geben 3 Punkte, kein Maximum. **Silberschädel:** 15 in Truhen der Orte der Stufe 1; der Geizhals verkauft alle auf einmal (1 000 Gold für die Gruppe und 1 000 XP je Held und Schädel), der fünfte bringt einmalig einen zufälligen Ring der Stufe 2.

### Action-System (`src/actions`)

Arten (`ActionKind` in `actions/types.ts`, Schema und Eigenschaften in `registry.ts`): u. a. `treasure, door, trap, lore, transfer, service, ambush, shrine, fountain, breakable_wall, decor, riddle, gong, lever, head, teleporter, talent, stairs, crystal, king, keeper, tube, portal, work, legacy`. `ACTION_DEFS` hält je Art `trigger` (`enter` = beim Betreten, `interact` = beim Anstoßen, Zelle blockiert), `persistence` (`once`/`repeat`), Kartensymbol und ein zod-Schema. **Immer `actionTrigger(a)` und `blocksCell(a)` benutzen**, nie `ACTION_DEFS[kind].trigger`. Eine Instanz hat `uid = "<mapKey>#<ruleId>:<n>"` (stabil, Schlüssel der Spielstand-Deltas).

**Regelmotor** (`rules.ts`, Regeln in `src/data/rules/{dungeon,cave,fortress,town,traps}.json`):

```json
{ "id": "chest_deadend", "kind": "treasure", "anchor": "deadEnd",
  "when": { "minDepth": 200 }, "count": { "perMap": [2, 5] },
  "params": { "level": "=tier", "gold": "=tier*90+rand(0,120)", "items": "=rand(0,1)" } }
```

- `count`: `perMap: [min,max]` oder `chance` (Promille je Anker); `when`: `minDepth/maxDepth` (Promille der Tiefe), `minTier/maxTier`, `minRoomSize`, `excludeEntranceRoom`; `variants`: gewichtete Parametervarianten; `assign`: verteilt Dienste an Stadtgebäude.
- Parameterwerte mit `=` sind Ausdrücke (`expr.ts`): `+ - * /`, Klammern, Variablen `tier, depth, depthRatio, mapTier`, Funktionen `rand(a,b)`, `min`, `max`; kein `eval`, keine Floats.
- Reihenfolge der Regeln = Reihenfolge der Dateien. Ein Belegungsraster verhindert Überlappung; vor dem Setzen eines blockierenden Objekts prüft `wouldDisconnect`, dass die Karte zusammenhängend bleibt. **Objekte stehen nie in einem Durchgang von einem Feld und lassen in einem breiteren einen Weg herum** (`interiors/passage.ts`: `splitsRing`, `blocksPassage`; Städte `splitsHere`, sonst `splitsPassage`), auch begehbare. Objekte kehren den Rücken einer **echten Wand** zu (`faceOpen`).
- **Die Objektliste des Nutzers gilt für alles, was der Generator stellt** (`item-rules.ts`: `allowedIn`, `isFunctional`): ein funktionales Objekt (Truhe, Fass, Hebel, Tor, Altar …) ist nie reine Deko, Personen nur in Burgen und Städten. `validateContent` prüft es (`itemIssues`), `plainProps(theme)` filtert die Deko.
- **Validierung** (`validate.ts`, im Test über 500 Seeds je Art): eindeutige UIDs, nichts auf Wänden (Ausnahme brüchige Wände), keine Überlappung, alles erreichbar, Spawnbereich frei, Landezellen reserviert, Parameter gültig.
- **Handler** (`handlers.ts`): `resolveAction(action, ctx)` ändert die Gruppe und liefert `Effect[]`; die UI (`Game.applyEffects`) setzt sie um. Ein neues Quest-Objekt braucht eine Aktionsart (`registry.ts`, `types.ts`), einen Handler, `GEN_VERSION` und `golden:update`.

**Schlösser und Fallen:** die Schwierigkeit eines Schlosses wächst mit der Gruppenstufe und wird erst bei der Probe aus `lockDifficulty(kind, tier, level)` gerechnet (`data/locks.ts`, Regeln und Herleitung `docs/THIEVERY_SCHLOESSER.md`); der Generator setzt nur die Marke `difficulty` 1. Gitter, Fässer, Brunnen, Kelche und Quest-Kisten haben nie ein Schloss. Unverschlossene Kisten tragen mit 20 % eine Falle (`data/chest-traps.ts`); Fallen der Dungeons sind sichtbar wie die der Kampagne (`render/interiorTraps.ts`) und wiederholen sich. Schaden mal `1 + Stufe / 10` (`trapDamageFor`).

## 8. Spielmechanik (`src/sim`)

Alles ist reines, JSON-serialisierbares TypeScript (`Party` und `Character` sind Plain Objects). Die Formeln sind Ports aus `old_code/g.py` und `entities.py` und seit Balance v4 angepasst; **alle Zahlen und Formeln stehen in `docs/FORMULAS_1.3.md`**, die Tests (`sim.test.ts`, `balanceV4.test.ts`, `combatFixes.test.ts`) pinnen sie.

- **Gruppe und Helden:** vier Standardhelden (`createDefaultParty`, Startgold 2 000); im Gasthaus (Buch der Helden, `sim/roster.ts`) lassen sich Helden würfeln, ablegen (`Party.reserve`, höchstens 20), tauschen und entlassen. Talente und Achievements gehören der Gruppe (`Party.talents`). 7 Attribute (`str int per end spd acc lck`), Resistenzen, 15 Zustände mit Timern (`sim/conditions.ts`, `Character.conditionDue`; `addCondition` braucht immer die Spielminute). **Kampfformeln lesen Attribute und Resistenzen mit Ausrüstung und temporären Boni** (`attr(c, …)`, `resistance(c, element, mascot)`, nie `c.str` oder `c.resFire` allein; `attr()` liefert nie unter 1). Temporäre Attribut- und Resistenzpunkte liegen in `Character.mods.boon`, Zauberwirkungen am Helden in `Character.mods` und gehen mit ihrem `TimedEffect` (`advanceTime`); Rüstung und Tempo lesen `armor(c)` und `fightSpeed(c)`.
- **Zeit:** 1 440 Minuten je Tag, Nacht über `isNight`; pro Tag eine Ration Nahrung, ohne Nahrung kein Rasten. Ein Schritt dauert in Orten 1 Minute, im Freien 10 (Pathfinder: 7); **jede Aktion 1 Minute** (Angriff, gelungener Zauber ohne Ziel, Anstoßen an ein Objekt, Schriftrolle lernen), abgelehnte kosten nichts. Training 2 Stunden je Held, Rasten und Gasthaus setzen ihre Zeit selbst. Die Sim-Funktionen buchen die Minuten selbst (`spendAction`).
- **Items:** `generateItem(rng, treasureLevel)` (seedbar), Material nach Schatzstufe, Vor- und Nachsilben; 9 Ausrüstungs- und 20 Beutelplätze. Obsidian-Ausrüstung (Material 8) legt nur an, wer das Talent Arms Master hat (`needsArmsMaster`). Ringe tragen Schadenszuwachs in Prozent (`damageIncreased`).
- **Kampf** (`combat.ts`, `encounter.ts`): Gitterkampf, getaktet durch die Gruppe (`Game.onArrived` und die Angriffs-/Zauberpfade rufen `updateBattleMode` und `monsterTurn`). Reichweite der Gruppe und Aktionsradius der Monster `SHOT_RANGE`/`MONSTER_ACTION_RADIUS` = 7 (Quadrat); Sichtlinie `lineOfSight` (ein Diagonalschuss läuft nicht um eine Mauerecke); Wegsuche mit höchstens 80 Knoten, die Monster ziehen im Kampf nach (`wayToPlayer(…, taken)`); im Nahkampf hält die Gruppe ihr Feld (Schritte, Portale und Versetz-Zauber werden abgelehnt). Monsterschaden physisch `Wurf × 30 / (30 + Rüstung)`, dazu zusätzliche Fehlchance gegen Helden der Stufen 1 bis 3; ein verfehlter Schuss richtet nie Schaden an; „Causes Dead“ und „Eradication“ treffen mit halber Chance. Ein Zug (turn) ist ein Zug der Monster (`monsterTurn`, `endMonsterTurn`). Wer im Kampf Schaden auf Helden bucht, geht durch `applyHit` (Power Shield, Rift).
- **Zauber:** 78 aus der Tabelle des Nutzers `docs/SPELLS.md` (`spell-sheet.json`; seit `bug_fix_79` ist sie die Quelle, nicht mehr die Excel in `old_code`; Mana, Schaden, Schadensart, „Penetrating“ und Skalierung überschreiben dort `raw/SPELLS.json`, `tables.ts`), **alle wirken** (`isSpellImplemented`); Name und Beschreibung lesen alle Stellen aus `SpellDef.title`/`text`. **Beschreibung und Wirkung müssen übereinstimmen**: geändert wird entweder der Text (**in `docs/SPELLS.md`**, der Exporter hängt nur den Satz „Costs … mana per caster level“ an) oder der Zauber; Test `spellConsistency.test.ts`, `tools/dev/check-spell-consistency.ts`. Lernen (`learnBlock`): nur die Schule der Klasse (Arcane: Wizard, Archer; Clerical: Cleric, Paladin; Nature: Druid, Ranger; die anderen vier Klassen lernen nichts) und ab der Stufe des Zaubers. Dazu die Darstellung der Vielfachzauber: Linien (Cold Ray, Prismatic Light, Acid Spray), Schlangen (Summon Snakes, `Projectiles.snakes`, Modell `proj_snakes` aus `PROJECTILE_MODELS`, Bild `tools/assets/sources/ui/spell_summon_snakes.png` über `OWN_PICTURES` in `build-spell-icons.ts`), Gaswolke (Toxic Cloud, `Effects.cloud` bei der Gruppe, `Effects.wisp` an jedem vergifteten Monster, `Game.poisonFx`). Ein neuer Zauber: Zeile in der Tabelle, `sim/spells.ts` (`castSpell`), bei Wirkung auf Monster `sim/encounter.ts`, bei Reisen und Fenstern `Game.worldSpell`, Test in `spells23.test.ts`. **Zauber, die den Zustand prüfen müssen, bevor sie bezahlt werden**, prüft `Game.spellRefusal` (abgelehnt kostet nie Zauberpunkte); Versetz-Zauber stehen in `PARTY_MOVERS`; kein Zauber trägt die Gruppe in einen verschlossenen Endraum oder auf eine andere Turmetage. Zauberbilder sind ein Blatt (`ui/spells.webp` + `spells.json`), das Zauberfenster ein Raster von 9 × 4 (`SPELL_GRID`, wächst mit der größten Schule).
- **Wirtschaft** (`economy.ts`, Fenster `ui/services.ts`): Gasthaus, Schmied (Sortiment deterministisch aus `(root, poiId, Tag, Tier)`), Tempel (Heilen, Zustände, Wiederbeleben, Spende), Bank (mit Schiebereglern), Training (`100 × Stufe × (Stufe + 1)`, 2 h je Held, „Train all“ von der niedrigsten Stufe), Gilde (nur Lernen: ein Reiter je Held), Taverne (Gerüchte), Quartiermeister (lagert Gegenstände), Feilschen über Talente, Arbeitsvermittler (Tier 1). Dienststufe = Stufe der Stadt.
- **Talente:** verkauft die Aktion `talent` (Personas in den Städten, Verkäufer in `data/talent-sellers.ts`, Preis aus `TALENTS`, Änderungen in `TALENT_CHANGES`); Orientation, Perceptive, Swimmer, Bargainer, Merchant verkaufen Karawanen (`CARAVAN_TALENTS`); die Gildenmitgliedschaft der Gildenlehrling jeder Stadt. Besonderheiten: **Cartographer** schaltet die große Karte (nicht in der Kampagne), **Perceptive** lässt brüchige Wände erkennen und einschlagen (ohne es ist Anstoßen ein Wandkontakt), **Cave Explorer** (`game/caveSense.ts`) lässt die Gruppe in Höhlen vor brüchigen Wänden stehen bleiben, **Pathfinder** (7 statt 10 Minuten im Freien), **Body Builder** (+1 LP je Stufe), **Arms Master**.
- **Maskottchen** (`data/mascots.ts`, Wechsel immer über `setMascot`): Wolf tötet jedes Monster unter 10 % LP (Puls der Karte), Fee erhöht alle Resistenzen um 15 %, Orb erhöht den Schaden aller Angriffszauber um 20 % und leuchtet wie ein dauerhafter Lichtzauber (`hasLight`), Krähe zeigt alle Fallen, das Capybara hat keine Wirkung (immer in Starthaven hinter einer brüchigen Wand, Tasche `CAPYBARA_POCKET`); das Maskottchen in der Party fehlt an seinem Platz (Altaktion 13). Neue Aufrufer von `recalcValues`/`levelUp` geben `party.mascot` mit.
- **Monsterwahl** (`data/monsters.ts`, `world/difficulty.ts`): 91 Monster; Werte, XP (Entity 23), Treasure Level (Entity 24) und Fähigkeiten (Entity 8) kommen aus `monster-sheet.json` (aus `RPG_0.1.xlsx`; `tables.ts` legt sie über die Altdaten, `TERRAIN_OVERRIDES` und `EQUIPMENT_OVERRIDES` korrigieren einzelne Monster, nie `MONSTER_DATA.json` ändern). Höhlen und Dungeons ziehen ihre Monster aus der **eigenen** Stufe (`pickMonsters`), Wassermonster nie an Land (`hasLandMonster`), Hüttenmonster geben XP nach Weltgröße (`hutXpPercent`). Monster der Nutzer-Modelle: `USER_MONSTER_MODELS` in `data/monster-models.ts`.
- **Zustände und Lava:** Vergiftet 2 Tage, Krank 3, Wahnsinnig 4 (dann tot), Betrunken 12 Stunden, Schwach 1 Tag, Schlafend 8 Stunden, Verliebt 2 Tage; ein erneuter Treffer verkürzt um 2 Stunden. Lava `sim/lava.ts`; Alter `sim/aging.ts` (ab 80 Jahren).
- **Balance:** `sim/balance.ts` hält Schalter (`BALANCE.mode`, `v4`/`legacy`) und `RULES`. Der `legacy`-Zweig ist nur Rückweg (`FORMULAS_1.3.md` Abschnitt 9); **neue Kampfformeln nie am Modus vorbei einstreuen**.

## 9. Kampagne (`src/campaign`)

- **Datenquelle:** `tools/export/export_maps.py` liest die `.map`-Pickles mit einem Dummy-Unpickler und schreibt `public/assets/campaign/<slug>.json` (+ `index.json`): 34 Spielkarten und die Testkarte `0000`.

## 10. Rendering (`src/render`)

- **Engine:** Babylon.js über Tree-Shaking-Importe, WebGL2, `StandardMaterial` (keine eigenen Shader außer dem Plugin `sightLimit.ts`), `UniversalCamera` (FOV 1,15, Augenhöhe 1,7). Licht: Hemisphäre und Richtung am Tag, bei Nacht und unter Tage `NIGHT_GLOW`, dazu die Fackel der Gruppe als Ring (`TORCH`, mit „Light“ `TORCH_LIT`) und ein **Pool von zwei Lampenlichtern** (`Renderer.lamps`, `render/lamps.ts`: Kristalle, Lava, Kamin, Orb, Portal …; Lichter bleiben bei ihrer Lampe und blenden über `LAMP_FADE` ein und aus, jede Lampenquelle braucht einen stabilen `key`; Schuss- und Zauberlichter haben Vorrang). Keine eigenen Lichter je Objekt, keine Echtzeitschatten. **Der Babylon-Shader begrenzt Licht je Kanal auf 1**: Helligkeit von Modellen kommt aus `textureBoost` (`render/props.ts`), nicht aus stärkeren Lichtern. Nebel und Kamera-`maxZ` folgen der Sehdistanz; **hinter dem Nebelende wird nichts gezeichnet** (`sightLimit.ts`).
- **Koordinaten** (`heights.ts`): Kachel-x wächst nach Osten (+x), Kachel-y nach Süden = −z, Norden ist +z; Babylon ist linkshändig. **Babylon spiegelt jedes glTF in x**; Pipeline-Maße (`bounds`) gelten im glTF-Raum, auf `PropInstance.center` ist kein Verlass. Orte und Objekte blicken zur Himmelsrichtung `ir` ihrer Kartenzelle (0 Norden), die Enter-Aktion liegt davor; keine Zusatzdrehung für OBJ-Items. Die geladenen Monstermodelle blicken nach +z; **Blickrichtung neuer Modelle nie raten**, mit `sheet:monsters` bzw. einem Screenshot (vier Instanzen mit 0°/90°/180°/270° nebeneinander) prüfen.
- **Überwelt:** immer flach mit den Kachelmodellen des Altspiels (`usesTileModels`, `setTileModels` vor dem ersten Chunk): Berge und Wälder in `terrainMesher.ts` (`TILE_TREES`, `TILE_MOUNTAINS`), `meshChunk` baut pro Chunk Typed Arrays (ohne Babylon), `ChunkManager` streamt nach Entfernung mit Zeitbudget (Meshing im Hauptthread, kein Worker). Bäume und Berge sind im ganzen Sichtbereich die echten Modelle (`NEAR_CHUNKS` 3). Wege sind Kopfstein, jedes Bodenmaterial hat in `GROUND_TILES` sein 3D-Modell (`gnd_*`, nur nahe Chunks, `nearOnly`). Wasser: UV-Scroll nur in `TerrainMaterials`; `tex_water.webp` ist ein geteiltes Texturobjekt (nie `uScale`/`uOffset` daran ändern).
- **Environment** (Menü Graphics: **Flat / 3D Floor/Ceiling / Full 3D**, `render/environment.ts`, `Settings.environment`; Low und Medium sind Flat, High ist Full 3D): ab „floor“ gelten die Altmodelle des Bodens, die Bodenplatten und Decken des Nutzers, in „full“ dazu die Wandstücke. **Welche Textur welches Modell hat, steht allein in `FLOOR_MODELS`, `CEILING_MODELS`, `WALL_MODELS`**; der Mesher (`floorModelAt`, `ceilingModelAt`, `meshInterior` Option `models`) und `environmentModels(map, env)` lesen sie. Es gibt Modelle für Stadtboden (`blk_city_floor`), Burgboden (`blk_fortress_floor`), Höhlenboden (`gndx_dirt`), Dungeondecke und Höhlendecke (gestaucht auf halbe Höhe, `CEILING_RELIEF`), Dungeon- und Stadtwand (`blk_dungeon_wall`, `blk_city_wall`, eingeschlagen `blk_dungeon_wall_broken`); **Burg, Höhle und Raumschiff haben keine 3D-Wand, Burg und Raumschiff keine 3D-Decke, das Raumschiff keinen 3D-Boden** (vom Nutzer gestrichen, nicht wieder anlegen). Ein Bodenstück liegt mit seiner Fläche (`surface` im Register) knapp über dem flachen Quad (`TILE_BOTTOM_BY_MODEL`, Fugen der Höhlenkacheln `TILE_OVERLAP_BY_MODEL`). Dateien des Nutzers stehen aufrecht und werden von der Pipeline hingelegt (`ModelSpec.rotateX`). Nach dem Umschalten die Chunks mit `ChunkManager.rebuild` neu bauen. Flache Bodenkacheln siehe Abschnitt 12.
- **Innenräume:** `interiorMesher.meshInterior` baut Wände, Böden und Decken prozedural aus sichtbaren Quads (gruppiert nach Material und 16 × 16-Sektion), `InteriorView` verwaltet Materialien (je Theme, nie mit den Instanzen freigeben), Props, Türen (`interiorDoors.ts`: Holztür mit Scharnier, Gitter, Metalltor, Schiebetüren des Raumschiffs; Dauer jeweils die hörbare Länge des Tons), Fallen (`interiorTraps.ts`), Lichtlinien und Kristalle. Wandstücke behalten ihre Dreiecke; `PANEL_DEPTH` legt die Tiefe fest. **Objekte in generierten Innenräumen sind so hell wie die Wand daneben** (`PropRenderer.setReference`, `InteriorView.WALL_MEAN`). Lichtlinien (`glowLines.ts`) sind flache Bänder mit eigener Textur und additivem Material, kein `GlowLayer`.
- **Props** (`props.ts`): Thin-Instances je (Modell, Material); Modelle laden mit `useSRGBBuffers: false` und **ohne** `twoSidedLighting` bei OBJ-Modellen (`toStandardMaterial` setzt es nur für glTF mit Normal-Map). Wer Modelle oder Materialien ändert, prüft sie **unter Fackellicht**. Der tiefste Punkt eines Modells steht auf dem Boden (ein `lift` ist falsch); Dinge am Boden stehen mit der Unterkante auf dem Boden (`GROUNDED_ITEMS` in `data/item-tuning.ts`). Größenkorrekturen: `HEIGHT_FACTOR`, `WIDTH_FACTOR`, `*_SCALE` ebendort; Maße einer neuen Nutzerdatei vor dem Einbau an `bounds` des Registers prüfen (die Pipeline normiert nicht).
- **Monster** (`monsters.ts`): animierte GLBs mit Klon-Pool je Typ; Materialien und Texturen gehören dem Typ: **Instanzen nie mit `dispose(false, true)` entfernen** (alle Monster dieses Typs würden weiß oder schwarz). Erscheinende Monster blenden in 0,3 s ein; ohne Clip „Dead“ verschwindet das Modell sofort. Waffen und Schilde (`equipment.ts`, `GRIP_TWEAK`, Mixamo-Rigs `MIXAMO_GRIP`) sitzen in der Hand; neue Waffen mit Nahaufnahmen von vorn und hinten prüfen. Helligkeit der Monstertexturen `monsterBoost(mean)`, **neue Monster unter der Fackel messen** (`tools/dev/monster-lit.ts`). Gesehen wird nur, was die Szene hält: **Props gehören einem Besitzer und müssen mit ihm verschwinden** (Chunks `"cx,cy"`, `interior:<key>`, `campaign`, `campaign-fx`, `loot`).
- **Effekte** (`render/fx.ts`, Bilder und Zellnummern `render/fxSheets.ts`, Einstellung `Settings.effects` Off/Low/Full als sechster Schalter der Qualität): das Wasser der Brunnen (seit bug_fix_68: `obj_fountain` auf dem Stadtplatz und `ci_2` in der Überwelt mit einem **blauen Wasservorhang** vom Rand der oberen Schale ins Becken (Kegel, Mischung *combine*, `water_flow`), Tropfen **im Bogen aus der Spitze ins Becken** (das Tropfenbild des Nutzers `water_drop`), Wellenringen, Nebel und der Scheibe mit dem Lichtnetz `water_ripple`; der **Meerjungfrauenbrunnen** `ci_89` mit Strahl und Tropfen aus der Hornmündung), der **Uferschaum** der Überwelt (`render/foam.ts`, `fx_foam`), Halos, Funken, Rauch und Glut an Lampen (`LampKind.fx`), der Wasserspritzer beim Eintauchen, und der Einschlag der Zauber (`Projectiles` ruft `Effects.impact` am Ende eines Fluges: Feuer, Eis, Säure, Magie als 16 Bilder; Schüsse der Monster nicht, sie enden an den Augen der Gruppe: `launch(…, impact = false)`). **Alles sind Quads von Bildern**: ein dynamisches Mesh für alle blassen additiven Partikel, eins für die Tropfen und eins für den Rauch (*combine*, die Tropfen und der Rauch nach ihrem Alpha), eins je Einschlagart (normale Mischung `combine`, sonst brennt der Einschlag am Tag zu Weiß aus), je Brunnen eine Scheibe und ein Vorhang mit **eigener Geometrie** (die Farben folgen dem Licht, nie `Mesh.clone`), das Material geteilt; **alles Additive folgt dem Licht der Szene** (`fxLight.ts` `lightAt`); kein `ParticleSystem`, kein Renderpass, kein Licht aus dem Lampenpool. 0,1 ms je Frame mit sieben Brunnen in Reichweite. **Die Brunnen kommen über die Besitzer der Props:** `PropRenderer.watch` meldet jedes `setInstances`/`removeOwner` an `Effects` (Schlüssel Besitzer + Modell + Platz), eine Szene, die ihre Props abgibt, nimmt das Wasser mit (`tools/dev/check-fx.ts leave`). Ein neuer Brunnen (Modell) gehört mit seinen Maßen in `FOUNTAIN_SHAPES` (gemessen mit `node tools/dev/model-profile.mjs <glb>`, ein Test prüft sie gegen `bounds`). Bei Level „off“ lädt das Spiel die Bilder gar nicht. **Bildkonvention:** gerader Alpha (Alpha = Intensität, RGB = Farbe, die grauen Sprites weiß und im Code eingefärbt), Mischung SRC_ALPHA + ONE: vormultiplizierte Bilder mit ONE + ONE zeigten nach der WebP-Kompression helle Quadrate (der Encoder lässt Farbe in Pixel mit Alpha 0 hineinsickern, `exact` hilft nicht). Prüfung im Browser: `tools/dev/check-fx.ts`. **Dritte Runde (17. 11. 2026):** Vorhang und Strahl sind Rotationsflächen (`sheetData`, Profil in `FOUNTAIN_SHAPES`: Stadtbrunnen vom Rand der Urne über die Gesichter, Meerjungfrau als Hülle um die Wassersäule des Modells in deren Farbe), Tropfen halbtransparent und auf 20 %, Ringe bleiben im Becken, Loot ohne Halo, Prismatic Light mit Einschlag, Schüsse auf die Mitte des gezeichneten Körpers (`MonsterRenderer.bodyMiddle`); Einzelheiten, Messwerte der Kosten (`tools/dev/check-fx-cost.ts`) und Prüfwerkzeuge in `CLAUDE.md` („Effekte, dritte Runde“).
- **Fallstricke, die Zeit gekostet haben:** `Mesh.flipFaces` kehrt auch die Normalen um (stattdessen `flipWinding`); **farbige Kopien eines Modells (`PropRenderer.tinted`) brauchen eine eigene Geometrie**, nie `Mesh.clone` für Kopien mit eigenen Thin-Instances; **ein Prop-Besitzer, der Instanzen teilt, räumt nie fremde Materialien ab**; Pseudo-Objektnummern (301 bis 303, 304 bis 309, 310, 330, 331, 332) vor dem Vergeben gegen `OWN_MODELS` prüfen: ein doppelter Schlüssel überschreibt still.

## 11. Spielschleife, UI, Einstellungen, Audio

- **`Game`** (`game/game.ts`): Modi `title | overworld | interior` (Kampagne = `interior` mit `poiId` `campaign:<slug>`). Wichtige Methoden: `start/newGame/newCampaign/loadFromFile`, `beginPlay`, `enterOverworld`, `openInterior/exitInterior`, `openCampaignMap`, `onArrived` (Schritt beendet → Action, Loot, Monster), `onBlocked` (Anstoßen), `useAction/applyEffects`, `handleEvents`, `frame`, `save`.
- **Ladebildschirm:** jeder Weg in eine neue Szene läuft zwischen `Game.beginLoading` und `Game.endLoading` (wartet mit `whenDrawable`, bis alles zeichenbar ist, danach Musik, Ortsname, Entsperren; Tastatur währenddessen verworfen). Die Methoden sind async: **Skripte und Tests warten auf die Promises** (`enter`, `leave`, `campaign`, `newGame`), nicht auf Schlafzeiten. Das Ladebild geht vor dem Bau der Welt auf und lädt sein Bild vor dem Einblenden. **`Game.onArrived` hört nach jedem `await` auf, wenn die Szene gewechselt hat** (`fxEpoch`).
- **Bewegung** (`player.ts`): Gitterschritt mit Interpolation, 90°-Drehung, Kollision reine Kachellogik (`canEnter`); ein lebendes Monster sperrt seine Kachel, ein Schritt dagegen ist ein Angriff; **Monster werden nie auf die Zelle der Party gesetzt** (`Game.onPartyTile`).
- **UI** (`src/ui`): reines DOM/CSS, Schriften Cinzel und Almendra (die Original-Schrift `MATURASC.TTF` wird nicht ausgeliefert). Fenster mit wechselndem Inhalt haben feste Größen (Charakterbildschirm, Party-Fenster, Buch der Helden, `steady()`); Auswahl eines Helden zeigt immer Porträts (`pickHeroPortrait`). Bildblätter statt Einzeldateien: Item-Icons (`ui/items.webp`), Zauber (`ui/spells.webp`), Porträts je Held (`portraitSheets`), Kartensymbole (`ui/minimap.webp`); **neue Zustände, Items, Zauber gehören in die jeweilige Quelle des Blatts**, nie `<img src=icons/…>` für Einzeldateien.
- **Karten** (`game/minimap.ts`, `mapView.ts`): die Minikarte zeigt `MINIMAP_CELLS` (11) Zellen; die große Karte (nur mit Talent Cartographer) öffnet mit 25 Zellen, zeigt die Welt **einmal** und ist ab 81 Kacheln ein Bild der ganzen Welt (`minimapOverview.ts`, neue Kachelarten in `overviewColor`). **Wizard's Eye deckt nur die Minikarte auf** (goldener Rahmen), die große Karte zeigt erkundete Zellen; Monster zeigen die Karten nur im Sichtkegel (`Game.mappedMonsters`), **Detect Monster** überall; Fallen nur ausgelöst, sichtbar oder mit der Krähe; Ereignisse der Überwelt (Maskottchen, Hütten, Karawanen) tragen ein Fragezeichen (`Game.overworldEvents`).
- **Optionen** (Titel und Esc-Menü: Controls, Graphics, Sound, `Game.optionsMenu`): Zeilen ändern nur einen Entwurf, „Apply“ setzt um, „Back“ verwirft. Felder in `Settings` (`game/settings.ts`, `parseSettings` kennt Altformate); **Quality** (`game/quality.ts`: Low / Medium / High / Custom, setzt Environment, Texturen, Sehdistanz, Auflösung, Stadtfilme); **Sehdistanz** (`ViewDistance` close/medium/far: größte Sicht 10/18/25 Kacheln, Chunk-Radius 1/2/3); Texturqualität „high“ lädt `hd/tex` und die Seite neu; **Tasten** über `actionOf` (`game/keybindings.ts`); Lautstärke 0 bis 100 (50 = Vorgabe); Fade-out-Cursor, Show action keys, Animated town scenes (Filme `ui/town/town_<Dienst>.webm`), Show FPS.
- **Audio:** `AudioManager` (Opus/WebM, Autoplay-Sperre beachtet), `sound-table.ts` bildet Alt-Sound-IDs auf Dateien ab (9000er Effekte, kleine Zahlen Musikzonen). **Effekte spielen aus vorab dekodierten Web-Audio-Puffern** (`preloadEffects`), Dauern aus `durationOf`/`audibleDurationOf`. **Töne folgen dem, was gezeichnet ist** (Holztür 9052, Gitter 9034, Schiebetür 9056, Wandeinschlag 9007, Steine 9050 …, Robotertöne `data/robot-sounds.ts`). Schmerzlaut je Held nach `CONSTANTS.CHARACTER_FEMALE`.

## 12. Asset-Pipeline

Quelle: `../old_code/resources` (`OLD` in `tools/assets/lib.ts`) und `tools/assets/sources/` (handgemalte oder vom Nutzer gelieferte Dateien: Bodenkacheln, Modelle, Töne, UI-Bilder, Statussymbole, Kartensymbole, Itembilder; **im Git, nie aus `.ignore` oder von Hand nach `public` legen**). Ausgabe: `public/assets` (`OUT`), **generiert, nicht von Hand ändern**. Werkzeuge: `sharp` (Texturen → WebP), `@gltf-transform/*` und `obj2gltf` (OBJ → GLB), `meshoptimizer`, `ffmpeg-static` (Audio → Opus/WebM). Kein Blender, kein ImageMagick.

- **Stufen:** `build-textures.ts`, `build-models.ts`, `build-audio.ts` (dazu `build-flat-terrain.ts`, `build-minimap.ts`, `build-item-icons.ts`, `build-spell-icons.ts`, `build-portrait-sheets.ts`, `build-placeholder-icons.ts`, `build-hd-textures.ts`, `gen-mixed-tiles.py`, `gen-space-doors.ts`); `build.ts` ruft sie auf (die Modelle nicht: das ist `assets:originals`), schreibt `manifest.json` (Gruppen mit Dateiliste und Bytes) und bricht ab, wenn der Kern 40 MB oder alles 250 MB übersteigt. Gruppen: `core` (vor dem ersten Frame), `campaign`, `interior:*`, `music:*` (lazy), `screens`, `terrain-flat`, `fx`, `outro` (nur am Spielende, außerhalb des Kerns).
- **Das Spiel lädt nur die Originalmodelle** (`npm run assets:originals`, `models-original/` mit eigenen Registern `models.*.original.json`, optional, zählt nicht zum Größenbudget). Der reduzierte Satz (`assets:models`, `models/`, `PROFILES.reduced`) ist seit bug_fix_68 gelöscht: es gibt nur dieses Profil, `--original` ist nur noch ein Name. **Ein neues Modell bauen** (`--only=<Schlüssel>`; `npm run assets:originals`), sonst „Unexpected magic“ beim Laden; ein eingefrorener Vite-Server liefert neue Dateien erst nach einem Neustart.
- **Teilbauten:** `assets:build` schreibt ein Manifest neu (die Modelle baut es nicht mehr). Nach Änderungen an `build-models.ts` den Zeitstempel zurücksetzen (sonst baut alles neu); für ein neues Modell nur `--only=<Schlüssel> [--original] [--force]` laufen lassen und das eingecheckte Manifest um die neuen Dateien ergänzen. Der Worktree braucht für die Pipeline eine Junction `.claude/worktrees/old_code`, danach mit `cmd /c rmdir` entfernen. Die Pipeline liest nur die ersten 60 000 Zeichen von `add_monster` (`readStaticMonsterMap`): Fälle am Ende bekommen Maßstab 1 (`SIZE_FACTOR` in `render/monsters.ts`).
- **Modelle:** Budgetprofile je Modellart (`HEAVY` 4 500 Dreiecke, POI 9 000); Normalen statischer Modelle sind `crease` (`CREASE_ANGLE` 75°), `flat` nur bewusst je Modell; die Pipeline misst `bounds`, `surface`, `mean` (mittlere Texturhelligkeit, Grundlage von `textureBoost`/`monsterBoost`) und `groundTop`. Dateien des Nutzers stehen aufrecht (`ModelSpec.rotateX`), Quelle `new:<Datei>`; **Maße und Blickrichtung einer neuen Datei vor dem Eintragen messen** (Dreiecke des Registers, vier Instanzen mit 0°/90°/180°/270° nebeneinander). Ersatz alter Items: `REPLACED_ITEMS` in `build-models.ts` (`Castle.glb` für Item 44, Dorf, Laterne, Meerjungfrauenbrunnen, `Power_crystal.glb` für Item 67, …); Nutzer-Monster mit `--monster=<ids>` (Mixamo-Rig).
- **Flache Bodenkacheln der Überwelt** (`terrain/flat/**`): handgemalte Quadrate aus `tools/assets/sources/terrain-flat/`, von `build-flat-terrain.ts` nach WebP gebracht und in `terrain/flat/tiles.json` beschrieben (Vollkacheln, Paare mit 14 Formen, Mischkacheln `mix_…` für Kopfstein + Wasser + ein Land aus `gen-mixed-tiles.py`; nie die Quellen der Paarkacheln ändern, ein neuer Boden oder eine neue Mischung gehört in dessen `LAND`/`STYLES`). **Eine Kachel gehört dem Gelände, das mehrheitlich abgebildet ist, bei Gleichstand dem ersten im Namen** (`parseFlatName`). Die Kacheln liegen auf den **Ecken** der Karten-Felder (vier Felder = vier Viertel eines Bildes); die Wahl trifft `FlatTileSet.pick` (`render/flatGround.ts`), nie von Hand. Wasser färbt `calmWater` beim Bauen um (nie die Quellen überschreiben). Zählen von Ecken ohne Kachel: `tools/dev/corner-stats.ts` (null).
- **Weitere Quellen mit eigener Regel:** Kartensymbole `ui/minimap.webp` + `minimap.json` aus `build-minimap.ts` (gemalte Kacheln für Orte, Ereignis und Ausgang in sechs Böden, Wiese und Sumpf macht das Skript aus der Wüstenzeile); Statussymbole aus `tools/assets/sources/status-icons/`; Bilder der Sprecher aus `sources/ui`; Töne aus `sources/audio` (`TRIM_TAIL` schneidet Stille am Ende, eine neue Fassung braucht ein gelöschtes Webm). Texturen „high“: `npm run assets:hd` nach `hd/tex/`, nicht im Budget.
- **Effekt-Grafiken** (`tools/assets/sources/fx/`, `build-fx.ts` → `fx/*.webp`, Gruppe `fx` im Manifest, `npm run assets:fx`): Partikelblatt 8 × 8 (128 px), Rauchblatt, fünf Einschlag-Flipbooks (4 × 4 à 256 px), nahtlose Wassertexturen (`water_ripple` addiert, `water_flow` blau mit eigenem Alpha), das Tropfenbild des Nutzers (`water_drop`) und der Uferschaum (`foam`, 512², nahtlos aus einem Flux.2-Bild des Governors, `foam_tex.py`). Erzeugt mit den Skripten in `tools/assets/fx/` (Anleitung dort): graues Partikelpaket des Nutzers (Kenney, CC0), Bilder des AI Governors und des Nutzers, Rest prozedural. Die Flipbooks sind aus je einem Bild berechnet. Nach Änderungen an den Quellen `assets:fx` laufen lassen und die Gruppe `fx` im eingecheckten Manifest nachziehen.
- **Ausgeschlossen** (nie ausliefern): Original-MM3-Dateien in `old_code/documentation/`, `MATURASC.TTF`, das PDF-Handbuch, `models_compressed/`, `maps/_old`. **Herkunft:** `tools/assets/reports/provenance.json` listet die Dateien; einige Texturen tragen Metadaten-Marker, die auf KI-Werkzeuge hindeuten (C2PA, OpenAI, Designer): ein Indiz, kein Beweis; **vor einer Veröffentlichung** die Nutzungsbedingungen prüfen.
- **Bekannte Lücken:** kein KTX2 (WebP liegt unkomprimiert im GPU-Speicher; die Originalmodelle brauchen viel Grafikspeicher), das Icon `item_2h_long_bow_copper` fehlt im Altbestand (Rückgriff).

## 15. Umgebungshinweise für Agenten

- **Windows 11.** Bash-Tool ist Git Bash (POSIX), daneben PowerShell; das Arbeitsverzeichnis ist im Bash-Tool persistent: absolute Pfade oder `cd "…" &&` je Befehl. Chrome-Pfad fest in `tools/dev/*.ts`.
- **Ein Sicherheits-Hook blockiert** `rm -rf`, Heredocs mit `${…}`, `>(` oder Backticks (auch `Map<number, X>()` in einem Skript) und Umleitungen auf dynamische Pfade. Nicht umgehen: Dateien mit dem Schreib- oder Edit-Werkzeug anlegen, statt zu löschen einzelne Dateien entfernen (`git rm`). **Nie `sed -i` auf CRLF-Dateien** (entfernt die Zeilenenden; `game.ts`, `quest-table.ts` und `HANDOVER.md` sind gemischt).
- **`game/dist` nicht anlegen oder verändern** (der Nutzer hat den Ordner absichtlich gelöscht). **Temporäres** gehört nicht nach `game/` und nicht nach `/tmp`, sondern in das vom Werkzeug genannte Scratchpad- bzw. Job-Temp-Verzeichnis.
- **Git:** ein Zweig je Auftrag (Worktree unter `.claude/worktrees/<name>`), Commit und Push laufen automatisch (Stop-Hook `tools/dev/auto-commit-push.sh`, nie auf `main`, nie `--force`); Pull Request und Merge, danach `git pull` auf `main` und den Worktree entfernen (`ExitWorktree` mit `remove`; die `node_modules`-Junction zuerst allein mit `cmd /c rmdir <Pfad>\node_modules` lösen). **Nie einen Worktree entfernen, der ungemergte oder ungepushte Commits trägt.** Ein Worktree ist eine volle Kopie (ca. 650 MB, 3 000 Dateien): liegen viele herum, antwortet der Dev-Server minutenlang nicht.
- **Eigener Vite-Server nur auf freiem Port** (der Port eines anderen Jobs lieferte schon Screenshots des falschen Worktrees); parallele Änderungen: eingefrorener Server (Abschnitt 2).
- **Antworten an den Nutzer** auf Deutsch mit korrekten Umlauten; Code, Kommentare, UI-Texte und Commit-Texte Englisch.
